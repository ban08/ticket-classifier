# Sistrade Ticket Classification ML POC

This repository contains a university proof of concept for Assignment 2 in Artificial Intelligence. The assignment asks for a realistic low-hanging-fruit machine learning problem, an ML model trained with artificial data, a small web app illustrating the model, and final code plus presentation material.

The chosen context is Sistrade customer support. Sistrade receives many support tickets that must be read, classified, prioritized, and routed by staff. This POC predicts useful triage fields so a support person can review a suggested classification before assigning the ticket.

This is not a production system and it is not a chatbot.

## Business Problem

Support staff may classify tickets incorrectly when they are busy, tired, or missing context. A ticket can be sent to development when it is only a client misunderstanding, marked low priority when it blocks invoicing, or assigned to the wrong department.

Better initial classification can reduce wasted staff time, shorten response delays, route urgent problems faster, and avoid unnecessary escalation. This makes ticket classification a practical low-risk ML POC: it supports human triage without directly answering customers.

## Why Classification Instead Of A Chatbot

A chatbot that answers clients directly is attractive but too broad and risky for this assignment:

- LLMs can hallucinate or invent company-specific details.
- Internal support knowledge may be recent, private, or undocumented.
- Wrong automatic answers can create business risk.
- LLM quality is harder to evaluate with simple deterministic metrics.
- Paid APIs may be required.

This project uses classic local ML with scikit-learn. The same input produces the same prediction, and the model can be evaluated with accuracy, precision, recall, F1-score, and confusion matrices.

## Dataset

The dataset is synthetic and generated by `src/generate_data.py`.

It contains 1,400 fake Sistrade-like support tickets with:

- `ticket_id`
- `client_name`
- `client_sector`
- `ticket_subject`
- `ticket_description`
- `module`
- `component`
- `urgency_signals`
- `previous_classification`
- `correct_ticket_type`
- `correct_priority`
- `correct_target_team`
- `preferred_resolver`

The generated text includes Portuguese and English wording, ERP vocabulary, ambiguous descriptions, urgency signals, incomplete user notes, and intentionally wrong previous classifications.

Because the data is artificial, the evaluation only proves that the workflow works on a controlled synthetic scenario. It does not prove real-world performance on Sistrade tickets.

## Model

The training script builds one deterministic classifier per output label:

- `ticket_type`
- `priority`
- `target_team`
- `module`
- `component`

Each final classifier uses:

- TF-IDF text features with unigrams and bigrams
- Logistic Regression
- fixed random seed

The script also trains a Multinomial Naive Bayes baseline for comparison. The saved artifact is:

```bash
models/ticket_classifier.joblib
```

The prediction layer returns predicted labels, confidence scores when available, and a short deterministic explanation based on keyword rules. The explanation is not generated by an LLM.

## Install

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Generate Data

```bash
python src/generate_data.py
```

This creates:

```bash
data/synthetic_sistrade_tickets.csv
data/data_generation_notes.md
```

## Train The Model

```bash
python src/train_model.py
```

This creates:

```bash
models/ticket_classifier.joblib
reports/model_metrics.json
```

Current synthetic test metrics:

| Label | Accuracy | Weighted F1 |
| --- | ---: | ---: |
| ticket_type | 1.0000 | 1.0000 |
| priority | 0.9929 | 0.9928 |
| target_team | 0.6179 | 0.6157 |
| module | 0.8929 | 0.8957 |
| component | 0.6714 | 0.6776 |

The weaker `target_team` and `component` results are useful warning signs: routing and detailed component prediction are harder and would need real historical data before real deployment.

## Run Sample Predictions

```bash
python src/predict.py
```

You can also pass a custom ticket:

```bash
python src/predict.py \
  --subject "URGENTE - erro ao emitir fatura" \
  --description "Estamos sem faturar, aparece exception no IVA e os utilizadores ficam bloqueados." \
  --client-sector "printing" \
  --urgency "sem faturar; ASAP" \
  --previous-classification "client_misunderstanding / medium / support_level_1"
```

## Run The Web App

```bash
streamlit run app/streamlit_app.py
```

The app lets a user enter a ticket subject, description, client sector, previous classification, urgency notes, and preferred resolver. It shows predicted classifications, confidence scores, and deterministic keyword evidence.

## Run Tests

```bash
pytest
```

The tests check deterministic predictions, output schema, urgent ticket behavior, and plausible module classification for invoicing/accounting examples.

## Limitations

- The dataset is synthetic and rule-generated.
- The results may be optimistic because the training and test examples come from the same generator.
- The app is a POC for human triage, not an automatic resolver.
- No real Sistrade customer data is used.
- No business integration, authentication, monitoring, or production deployment is included.
- Confidence scores are model probabilities, not guarantees.

## Future Improvements

- Replace synthetic data with anonymized historical tickets.
- Add human review feedback to retrain the model.
- Tune models per label and compare more algorithms.
- Add confidence thresholds so uncertain tickets are flagged for manual review.
- Improve component and target-team labels with richer operational data.
- Integrate with a ticketing system only after validation with real users.
