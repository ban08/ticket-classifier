# Model Evaluation

## Dataset

The dataset contains 1,400 synthetic support tickets generated by `src/generate_data.py`.

The model predicts five labels:

- `ticket_type`
- `priority`
- `target_team`
- `module`
- `component`

The data is split into 80 percent training and 20 percent test data using a fixed random seed. The split is stratified by `correct_ticket_type`.

## Algorithms Tested

Two classic text-classification approaches were tested:

- TF-IDF + Multinomial Naive Bayes baseline
- TF-IDF + Logistic Regression final model

Logistic Regression was selected as the final model because it gives strong performance across most labels and provides probability estimates for confidence scores.

Naive Bayes slightly outperformed Logistic Regression for `target_team`, but Logistic Regression was kept as the final consistent model family because it performed better on the other labels and keeps the implementation simple.

## Interpretation

The high scores for `ticket_type` and `priority` show that the synthetic generator creates clear textual clues for these labels. This is useful for a classroom POC, but it also means the numbers are optimistic.

The lower scores for `target_team` and `component` are realistic warning signs. Routing a ticket to a team depends not only on text, but also on internal workload, ownership rules, customer history, and resolver expertise. Component prediction is detailed and harder because many components share similar words.

## Limitations

- The dataset is artificial and does not represent real Sistrade performance.
- The same generator creates both training and test examples.
- Real tickets would include more spelling variation, missing context, attachments, and domain-specific phrases.
- The model should be treated as a triage assistant only.
- Before any real deployment, the model would need anonymized historical data, human validation, and monitoring.
